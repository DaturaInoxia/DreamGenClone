## 1. Problem

Two coupled issues surfaced after the first successful B-100 Composition render:

### 1a. The Composition stage is a black box (UX)
The exact prompt, render settings, and image model all live under the collapsed
**"Legacy and experimental image tools"** region (`Production Image Prompt` + `Image Settings`),
visually disconnected from the Production Studio. The user cannot:

- see the **actual prompt** being sent,
- change **how it renders** (size / CFG / steps / sampler / scheduler / negative),
- change the **model** (it auto-resolves `RolePlaySceneImage` → `bigLust_v16` via RunPod Serverless BigLust).

Functionally the knobs exist and are threaded end-to-end
(`SettingsJson` → `ResolveGenerationOptions` in `SceneImageRenderingJobHandler`), but they are not
surfaced in the production flow.

### 1b. The generated prompt ignores SDXL/BigLust best practices (fidelity)
The Dean render (`SceneImages` `71cf6f2a`, `bigLust_v16` · RunPod Serverless BigLust ·
1024×1024 · realistic) used this prompt:

> *"Wide night still from Dean's deck: Dean holds motionless in the lower foreground, arms loose at
> his sides, a dark silhouette against humid darkness, watching across twenty feet of open grass.
> Becky stands at the far trailer rail wearing only Ken's unbuttoned pale-blue camp shirt,
> bare-legged, a glass set on the rail before her, face turned toward the dark pines. Porch light
> is off; thin strips of blue TV light leak through warped blinds, striping her skin, while the
> deck is otherwise swallowed in shadow. 35mm, natural skin texture, shallow depth of field,
> quiet, charged, suspended."*

Result: an image of **Dean (from behind) facing a trailer**, with Becky absent/buried. The model
dropped the distant, shadowed subject.

## 2. Root causes

### 2a. Where the prompt comes from
The composition prompt is generated by an **LLM preprocessor** (not hand-written) via
`SdxlSceneImagePromptBuilder.BuildCanonicalSystemPrompt` (the `CompiledMediaBrief` production
path). That system prompt says:

> *"Project the supplied immutable canonical Still brief into a concise 2-4 sentence photographic
> brief… Include the exact visible people, appearance, wardrobe, frozen action, location,
> lighting, mood, **production POV**, and photographic camera cues… Keep the result under 800
> characters."*

It never defines:

1. **POV framing** — what `PRODUCTION POV: <name>` means for the frame. So the LLM wrote the POV
   character (Dean) *into* the frame ("Dean holds motionless in the lower foreground") instead of a
   Dean-POV view of what he sees.
2. **No names / relations / ownership** — text-to-image models cannot map "Dean", "Becky", or
   "Ken's shirt". The LLM copied the brief's names instead of describing people visually.
3. **Visual-first description** — people were described by role/relation rather than build, hair,
   clothing type+color, pose.
4. **Renderable-only** — the prompt kept narrative distance ("watching across twenty feet"),
   intent, and metaphor ("swallowed in shadow") that have no visual mapping.

### 2b. Missing identity conditioning
The **Identity** stage (approved character reference projection) is **not implemented** in this
boundary ("approved reference projection and source-image identity editing are not implemented in
this boundary"). Without reference images, "Becky looks like Becky" cannot be enforced — the model
must rely entirely on the text description.

---

## 3. Prompting best-practices guidance (the fix rules)

When generating a composition prompt for SDXL-family checkpoints (SDXL / Juggernaut / BigLust):

1. **POV framing** — Render the scene strictly from the `PRODUCTION POV` character's viewpoint:
   render only what that character sees; **never include the POV character in the frame**.
2. **No names / relations / ownership** — Describe every visible person by physical appearance
   (build, hair style/color, clothing type+color, visible pose). Never use story names,
   relationships, or property ("Ken's shirt").
3. **Renderable-only** — Include only what is visually renderable at the frozen instant: people,
   clothing, hair, pose, location, objects, lighting, camera. Omit narrative distance, intent,
   metaphor, and off-screen facts.
4. **Tight photo caption** — Output a ~600–800 char photographic caption; lead with framing and
   subject.

### Target shape (user's example)
> *"a photo realistic 20 feet away of a woman, wearing a blue button shirt, hair in a bun…
> (text description), standing on a deck at night at a trailer (more description)"*

### Corrected Dean-POV prompt (draft, applying the rules)
> *"A photorealistic view from twenty feet away across the grass at night: a woman with dark hair
> in a loose bun stands at the wooden deck railing of a silver trailer, wearing an unbuttoned
> pale-blue button-front camp shirt, bare-legged, one hand resting beside a glass on the rail, her
> face turned toward the dark pines. She is lit only by thin strips of blue television light
> leaking through warped blinds; the porch light is off. 35mm, shallow depth of field, natural
> skin texture."*

No Dean in frame, no names, no "Ken's shirt", no metaphor — only what Dean sees.

## 4. Proposed design (3 parts)

- **(A) Surface in the Composition stage** (medium, quick win):
  - exact-prompt preview + edit with live word/token count and a "view submitted payload" link
    (the render already logs `SceneImageRequestSubmitted` with positive/negative/seed/checkpoint),
  - a resolved-render badge (model · provider · size · style · steps/CFG),
  - protocol-aware render controls (Size / CFG / Steps / Sampler / Scheduler / Negative),
  - a **model selector** (image-capable models for `RolePlaySceneImage`), persisted per
    group/session instead of auto-resolve.
- **(B) Prompt-level fix now** — harden `SdxlSceneImagePromptBuilder.BuildCanonicalSystemPrompt`
  with the 4 rules above, regenerate, and re-render to prove Becky lands in frame. No UI change.
- **(C) Larger follow-on** — implement **Identity / reference projection** (approved character
  reference images) so characters render consistently; the Identity/Finish tabs are currently
  stubbed.

**Recommendation:** A + B now; C as a separate feature.

## 6. Open questions

- Should the POV rule apply to **Omniscient** POV as well (there, the POV character *is* in
  frame), or only to named observer POVs? **Proposal:** Omniscient = full scene (all characters
  visible); named POV = only what that character sees (POV character excluded).
- Model selector: persist per production group, per session, or global studio default?
- Should the model selector be protocol-aware (only list models compatible with the current
  provider/protocol), or free-range across all image-capable models?
