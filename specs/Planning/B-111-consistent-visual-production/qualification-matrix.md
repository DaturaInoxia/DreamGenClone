**Cell count:** 6 configured image endpoints × 7 C3 strategies = **42 cells**.

## Classification rules

- **qualified** — a **B-111 scorecard** (identity/adherence/diversity triple, produced by `tools/consistency-scoring`) exists for this exact `(strategy, model, endpoint, strength)` and passes its calibrated thresholds (FR-C3-02). **Pre-B-111 POC/registry proofs do NOT qualify** — they are recorded inline as *prior evidence* and are strong P3 re-qualification candidates, but they predate the scorer and must be re-proven through it (G6).
- **unqualified** — the provider class/graph can host the mechanism, but this endpoint has no passing proof for the cell. A failed probe is also not qualification.
- **structurally-impossible** — the endpoint class cannot host the mechanism, or the endpoint's documented worker lacks the required custom node. Hosted OpenAI-image endpoints have no ComfyUI graph.

The B-111 C3 strategy contract names `TextOnly`, `ReferenceEdit`, `IpAdapter`, `PuLid`, `IpAdapterFaceId`, `InstantId`, and `Lora` ([B-111 spec](../../../specs/Planning/B-111-consistent-visual-production/spec.md)). The current domain enum has only `Unknown`, `IpAdapter`, and `PuLid` ([CharacterImageIdentityModels.cs](../../../DreamGenClone.Domain/RolePlay/CharacterImageIdentityModels.cs)); the missing contract names are recorded here as unimplemented/unqualified strategy cells, not inferred enum values.

The provider protocol classes are `OpenAiImages`, `ComfyUi`, and `ComfyUiServerless` ([ImageProtocol.cs](../../../DreamGenClone.Domain/ModelManager/ImageProtocol.cs)). The DB inventory below was produced by the SELECT-only query [b111-qualification-matrix-inventory.sql](../../../DreamGenClone.DbQuery/queries/b111-qualification-matrix-inventory.sql). Providers with `ImageCapability = None` (LLM/compiler-only providers) are not image endpoints for this table.

## Moving a cell to qualified

B-111 P3 requires an isolated proof for the exact `(strategy, model, endpoint, strength)` tuple, a recorded scorecard using the identity/adherence/diversity triple, and the resulting qualification record before production selection ([B-111 P3 plan](../../../specs/Planning/B-111-consistent-visual-production/plan.md), [B-111 spec](../../../specs/Planning/B-111-consistent-visual-production/spec.md)). For the serverless PuLID cells currently marked structurally-impossible, first ship the required worker image/custom-node stack and record that deployment in the RunPod registry; only then can the isolated proof and scorecard move a cell through unqualified to qualified ([pod-registry.json](../../../helpers/runpod/pod-registry.json)).
