## Common Pitfalls

- **Forgetting the no-fallback contract**: A `Scoring` source is the BASE path and must NOT log a warning. A `Fallback` source is reserved for "LLM was attempted and failed." Mixing them in code triggers the repo's no-fallback guard rails.
- **Persisting the cache**: `LastActorOrdering` and `LastContextFingerprint` are transient — do NOT add columns for them. They invalidate on session reload by design.
- **Dedupe key shape**: MUST be `$"location:{sessionId}"`, not per-interaction. Per-interaction keys would let stale jobs overwrite fresh state.
- **Persona handling**: Persona is NOT a candidate in the LLM call; it's inserted after the LLM returns. Don't pass it in `Candidates`.
- **B-056 aftermath bypass**: The new pipeline runs AFTER the B-056 guard returns — preserve the existing return statement at L2279–L2283.
- **OtherMan opening exclusion**: `totalInteractions < 6` filter (L2403) is a pre-filter before the new pipeline — keep its location.
- **`BehaviorModeService.GetAllowedActors`**: The pipeline runs AFTER this filter at L2317 — don't bypass it.
- **Scene location types**: `CurrentSceneLocation` stores `Location.Name`, not `Location.Id`. Affinity matching uses `string.Equals(name1, name2, OrdinalIgnoreCase)`. Don't accidentally key by ID.
- **Time-of-day keyword word boundary**: Use `\b` regex or split-and-contains; "afternoon" must NOT match inside "afternoonschool". The existing codebase uses regex sparingly; either pattern is fine in this isolated keyword matcher.
- **Multiple affinity entries for the same location**: Per clarification Q1, multiple entries with distinct `TimeOfDay` values are allowed. The resolver must gather ALL applicable entries and apply precedence between them — not pick the first match.
