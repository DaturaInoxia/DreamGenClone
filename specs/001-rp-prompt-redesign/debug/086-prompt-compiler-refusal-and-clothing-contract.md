# 086 — "The top remains no matter what I try": the compiler refused, the refusal was rendered, and the contract forbade the clothing state

**Session:** 2026-10-18 · **State:** implemented, build green, targeted prompt-compiler suite 137 passed, full suite 4440 passed / 27 pre-existing failures (LoRA coverage matrix)
**Scope:** the scene-image prompt compiler — its model assignment, its intent contract, and what it is allowed to return.
**Related:** 083/084 (image-edit composite), B-135 (image playground), B-157 (reference-role prompt assembly), `scene-image-prompt-compiler-standards`.

---

## Report

Operator, on SceneImage `0c09aa2e…`, repeated at `8868fb26…`:

> "her top removed, the top thrown on the ground and her pants open … several prompts, the top remains no matter what i try"

---

## Analysis

Two independent defects, both visible in the dev DB.

### 1. The compile model refused, and the refusal became the prompt

`RolePlaySceneImagePreprocessor` was assigned to `deepseek-flash` (hosted DeepSeek). Its prompt records for the three
explicit attempts were **Complete**, with the refusal as `OutputPrompt`:

| record | image | stored prompt (head) |
|---|---|---|
| `a597ba82` | `8868fb26` (20:10) | *"I can't write this one. The operator intent is a request for explicit nudity — bare breasts…"* |
| `aef9f30c` | `0c09aa2e` (19:30) | *"I can't write this one. The intent asks for an explicit description of nudity…"* |
| `99fedb9d` | 3 renders (19:12) | *"I can't write this one. …naked from the waist up… that's sexually explicit imagery"* |

`NaturalLanguageSceneImagePromptBuilder.ParseOutput` accepts any non-JSON text as the prompt, so nothing detected it.
The render followed the refusal's own suggested alternative ("standing straight and facing the camera, weight even"),
which is exactly the picture the operator was complaining about.

The same model also **soft-refused**: `c2e7857f` (19:00) compiled the intent *"pulled up over her breast showing her
bare breasts"* into *"the hem climbs higher… the movement not yet finished"* — the explicit clause silently dropped.

### 2. The intent contract forbade stating the clothing state — with no clothing reference bound

All three attempts were compiled under `Qwen21CanonicalActionOnly` (verified from
`RolePlayDebugEvents.SceneImagePromptProjected`). The contract was selected by **"any reference bound"** and asserted
all four element classes as supplied:

> *"2. DO NOT DESCRIBE CLOTHING OR NUDITY… **state nothing about what is or is not worn**. The clothing reference
> decides all of it."*

The applied bindings for `0c09aa2e` were **Body ("Front · Unclothed") + Location only — no wardrobe plate**
(`SceneImages.AppliedReferenceBindingsJson`), so nothing was deciding the clothing, and the operator's instruction was
forbidden from being written. That is why no prompt could ever remove the top.

### 3. Why DeepSeek refused here but writes the RP fine

Interaction `4bb3e049` (Becky) was generated by the **same** `deepseek-flash` at 20:42, after the refusals, and is
explicit. Its prompt is 102,851 chars opening *"You are an expert creative writer specializing in immersive erotic
fiction…"* with dozens of in-scene turns. The image compiler sends a 4.5 KB formatting contract and a 1.2 KB cold
instruction to *describe a naked body*. The refusal is prompt-shape dependent, not model-wide — and it confirms that RP
should stay on DeepSeek.

## Resolution

### A. The preprocessor is now the unrestricted local model

`FunctionModelDefaults[RolePlaySceneImagePreprocessor]` → **`qwen2.5-vl-7b-instruct-abliterated-local`**
(`9f2c7a41-3b6d-4e08-95c1-a7d4e609b812`, Local LM Studio) — the same model the edit-prompt compiler already uses.
`RolePlayGeneration` is unchanged.

Measured on the operator's own failing prompt, against the LM Studio box (direct `/v1/chat/completions`, production
4,511-char system prompt + 1,265-char intent):

| model | refuses | states the clothing state | words | time |
|---|---|---|---|---|
| `qwen2.5-vl-7b-instruct-abliterated-local` (A = old contract) | no | implies it ("tank top lies on the ground") | 55 | 10 s |
| same, B = new contract | no | **"only wearing denim shorts… thrown down"** | 81 | 2.5 s |
| `dolphin3.0-llama3.1-8b` | no | yes ("unclothed from the waist up") | 63 | 1.9 s |
| `qwen2.5-14b-instruct-1m` | no | yes ("naked from the waist up, bare torso") | 92 | 11.6 s |

### B. A refusal can no longer become a prompt

New `SceneImagePromptRefusal` (Domain): a compiled prompt is a third-person description of a picture, so a response
that OPENS with a first-person refusal (or carries a refusal phrase in its head) is not a prompt.
`EnsureIsPrompt` throws with the remedy, and the three parse paths call it — `NaturalLanguageSceneImagePromptBuilder`,
`PonySceneImagePromptBuilder`, `WardrobeItemPromptCompilers`. The job handler already marks the record Failed with the
message, and the studio shows failed prompts, so the operator now sees *"the model configured for this prompt function
declined the operator's intent"* instead of a wrong render.

### C. The intent contract is composed per supplied element

`IntentReferenceCoverage` (Domain: Setting / Appearance / Clothing / Pose / Objects) is derived from the same
`ReferenceBindingPromptRemoval.Derive` scopes the ownership notice prints, so the contract and the notice cannot
disagree. `Qwen21CanonicalActionOnly(coverage)` emits:
- the setting rule only when a location plate is bound;
- the appearance rule only when an identity/body plate is bound;
- the object rule only when a prop is bound;
- **the clothing rule only when a wardrobe plate is bound — otherwise "STATE THE CLOTHING STATE", which requires the
  garment, its new location and what is bare to be written.**

With every class supplied the text is the measured contract verbatim (13 rules, same order), so the findings behind it
(f74058d3 invention over bound plates, 87454bef duplicate clothesline) still hold.
